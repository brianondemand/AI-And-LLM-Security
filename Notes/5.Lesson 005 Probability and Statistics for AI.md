## 1. Topic Introduction

**Probability** answers: *given how the world works, how likely is each outcome?* (Rules to data.) **Statistics** answers: *given data I observed, what can I conclude about how the world works?* (Data to rules.)

Machine learning lives in the space between them: we assume data comes from some underlying random process, and we use observed data to estimate it.

| AI concept | Probability/statistics idea |
| --- | --- |
| "87% chance this email is spam" | A probability from a classifier |
| The spam filter from Lesson 001 (Naive Bayes) | Conditional probability and Bayes' rule |
| Loss for classification and for LLMs | Cross-entropy (the negative log of a probability) |
| Converting scores into probabilities | Softmax |
| LLM "temperature" and sampling | Sampling from a probability distribution |
| Train/test split, evaluation | Sampling, variance, confidence intervals |
| Anomaly detection | Distance from the normal distribution (z-scores) |
| Weight initialization, dropout, noise | Random numbers from chosen distributions |

**Why it matters for security:**

- **Base rates decide whether a detector is useful.** Almost every alerting system, from intrusion detection to AI content filters, faces the *base rate fallacy* (Section 3.4).
- **LLM outputs are random samples.** An attack that works 3 times out of 10 is a real finding, and you need statistics to report it truthfully (Section 3.7).
- **Poisoning and drift change distributions.** Detecting them is a statistics problem.
- **Privacy attacks exploit probabilities.** Models are often more confident on data they trained on, which is the basis of membership inference.
- **Randomness quality matters.** Predictable random numbers are a classic vulnerability.

## 2. Fundamental Concepts

### 2.1 Vocabulary of randomness

| Term | Meaning | Example |
| --- | --- | --- |
| **Experiment** | Something with an uncertain result | Roll a die |
| **Outcome** | One possible result | Rolling a 4 |
| **Sample space** | The set of all outcomes | {1, 2, 3, 4, 5, 6} |
| **Event** | A set of outcomes we care about | "Roll an even number" = {2, 4, 6} |
| **Probability P(A)** | A number from 0 to 1 measuring how likely event A is | P(even) = 3/6 = 0.5 |

**Rules you can always rely on:**

- Every probability is between **0** (impossible) and **1** (certain).
- The probabilities of all possible outcomes add up to **1**.
- **Complement:** P(not A) = 1 - P(A). If P(rain) = 0.3 then P(no rain) = 0.7.

### 2.2 Two ways to think about probability

- **Frequency view:** probability is the long-run fraction. If you roll a fair die a million times, about one-sixth of the rolls will be sixes. You can *test* this by simulation, and you will in the lab.
- **Belief view:** probability measures how strongly we believe something given what we know ("I'm 80% sure this email is spam"). This view lets us update beliefs when new evidence arrives, which is what Bayes' rule does.

Both views use the same math. Modern ML uses both.

### 2.3 Equally likely outcomes

If all outcomes are equally likely, then:

```latex
P(A) = \frac{\text{number of outcomes in } A}{\text{total number of outcomes}}
```

**Example:** two dice, probability the sum is 7. There are 6 x 6 = 36 equally likely pairs. The pairs adding to 7 are (1,6), (2,5), (3,4), (4,3), (5,2), (6,1): six of them. So P(sum = 7) = 6/36 = **1/6**, about 0.167.

## 3. Technical Explanation

### 3.1 Combining events

**Independent events** do not influence each other (two separate coin flips). For independent A and B:

```latex
P(A \text{ and } B) = P(A) \times P(B)
```

Example: two heads in a row = 0.5 x 0.5 = **0.25**. Three heads = 0.5 x 0.5 x 0.5 = 0.125.

**"Or":** for events that cannot both happen (rolling a 1 or a 2): add them. P(1 or 2) = 1/6 + 1/6 = 1/3. If they can overlap, subtract the overlap so it is not counted twice:

```latex
P(A \text{ or } B) = P(A) + P(B) - P(A \text{ and } B)
```

**Gambler's fallacy warning:** after five heads in a row, the next flip is *still* 50/50. Independent events have no memory. Beware of this in security too: "it has not been attacked in a year, so it is due" is not a probability argument.

### 3.2 Conditional probability

**Conditional probability** is the probability of A *given that we know B happened*. Written P(A | B), read "probability of A given B".

```latex
P(A \mid B) = \frac{P(A \text{ and } B)}{P(B)}
```

The idea: knowing B shrinks our world to only the cases where B is true, then we ask how often A occurs within that smaller world.

**A worked example with counts (this is the spam filter in miniature).** We have 100 emails:

|  | Contains "free" | Does not contain "free" | Total |
| --- | --- | --- | --- |
| **Spam** | 24 | 16 | 40 |
| **Not spam (ham)** | 6 | 54 | 60 |
| **Total** | 30 | 70 | 100 |

From the table:

- P(spam) = 40/100 = **0.4** (the overall rate of spam)
- P(free | spam) = 24/40 = **0.6** (60% of spam contains "free")
- P(free | ham) = 6/60 = **0.1** (10% of normal mail contains "free")
- P(spam | free) = 24/30 = **0.8** (of all emails containing "free", 80% are spam)

**Notice P(free | spam) = 0.6 is very different from P(spam | free) = 0.8.** These are *different questions*. Confusing them is one of the most common reasoning mistakes in all of statistics (sometimes called the prosecutor's fallacy).

The question a spam filter must answer is the second one ("given this email contains 'free', is it spam?"), but the easy thing to measure from data is the first ("among spam, how often does 'free' appear?"). **Bayes' rule converts one into the other.**

### 3.3 Bayes' rule

```latex
P(A \mid B) = \frac{P(B \mid A)\, P(A)}{P(B)}
```

For our email problem, A = spam and B = contains "free":

```latex
P(\text{spam} \mid \text{free}) = \frac{P(\text{free} \mid \text{spam})\, P(\text{spam})}{P(\text{free})}
```

The four named parts:

| Part | Name | Meaning | Value here |
| --- | --- | --- | --- |
| P(spam) | **Prior** | What we believed before seeing the evidence | 0.4 |
| P(free given spam) | **Likelihood** | How likely the evidence is if the hypothesis is true | 0.6 |
| P(free) | **Evidence** | How likely the evidence is overall | see below |
| P(spam given free) | **Posterior** | Our updated belief after seeing the evidence | what we want |

The evidence is found by considering both ways it can occur:

```latex
P(\text{free}) = P(\text{free} \mid \text{spam})P(\text{spam}) + P(\text{free} \mid \text{ham})P(\text{ham}) = 0.6 \times 0.4 + 0.1 \times 0.6 = 0.24 + 0.06 = 0.30
```

So:

```latex
P(\text{spam} \mid \text{free}) = \frac{0.6 \times 0.4}{0.30} = \frac{0.24}{0.30} = 0.8
```

This matches the count (24 out of 30). Bayes' rule did not give us new information; it let us reach the same answer using quantities that are easy to measure separately.

**The big idea: Posterior = prior updated by evidence.** Start with a belief, see data, update. This is how learning from evidence works, and it is a recurring theme in AI.

### 3.4 Security essential: the base rate fallacy

This example is worth more than any other in this lesson for a security professional.

**Scenario.** An intrusion detection system (IDS) is described as follows:

- It detects **99%** of real attacks (true positive rate = 0.99).
- It raises a false alarm on **1%** of harmless events (false positive rate = 0.01).
- Real attacks are rare: **1 in 1,000** events (prevalence = 0.001).

An alert fires. **What is the probability it is a real attack?** Most people say about 99%. Let us compute it with Bayes' rule.

```latex
P(\text{attack} \mid \text{alert}) = \frac{0.99 \times 0.001}{0.99 \times 0.001 + 0.01 \times 0.999} = \frac{0.00099}{0.00099 + 0.00999} = \frac{0.00099}{0.01098} \approx 0.09
```

**About 9%.** More than nine out of ten alerts are false alarms, even though the detector is "99% accurate".

**The same thing with natural frequencies (easier to feel).** Imagine **100,000 events**:

- **100** are real attacks. The detector catches 99 of them (99%).
- **99,900** are harmless. The detector falsely alarms on 1% of them: **999** false alarms.
- Total alerts: 99 + 999 = **1,098**. Real attacks among them: 99.
- Fraction real = 99 / 1,098 = **9.0%**.

The flood of harmless events (the **base rate** of 99.9%) swamps the few real attacks. This is why alert fatigue exists, why SOC analysts distrust noisy tools, and why every AI content filter, malware classifier, and prompt-injection detector must be evaluated with realistic base rates, not just "accuracy".

| Lesson for defenders | Why |
| --- | --- |
| Report **precision** (what fraction of alerts are real), not only recall or accuracy | Precision depends on the base rate |
| Test detectors on data with realistic prevalence | A balanced 50/50 test set hides the problem |
| Lower the false positive rate drastically for rare threats | 1% is too high when attacks are 0.1% |
| Chain cheap filters with expensive ones | Reduces the number of events the costly step sees |

**Another warning, "accuracy" can lie:** if 999 of 1,000 events are harmless, a useless model that always says "harmless" is **99.9% accurate**. That is why Module 1.10 covers precision, recall, F1, and confusion matrices.

### 3.5 Describing data: mean, median, variance, standard deviation

**Mean (average):** add the values and divide by how many. **Median:** the middle value when sorted (half the data is below, half above). **Mode:** the most frequent value.

The mean is sensitive to outliers; the median is not. Data: \[10, 11, 12, 13, 1000\]. Mean = 1046 / 5 = **209.2**, which describes none of the points. Median = **12**. You saw this effect in Lesson 003, where outliers inflated the very standard deviation used to find them. **Median-based statistics are more robust against attackers who plant extreme values.**

**Variance and standard deviation** measure how spread out the data is.

**By hand.** Data: \[2, 4, 4, 4, 5, 5, 7, 9\]

1. Mean = (2+4+4+4+5+5+7+9) / 8 = 40/8 = **5**
2. Deviations from the mean: -3, -1, -1, -1, 0, 0, 2, 4
3. Square them (to make them positive): 9, 1, 1, 1, 0, 0, 4, 16
4. Add them: **32**
5. **Variance** = 32 / 8 = **4** (average squared deviation)
6. **Standard deviation** = square root of the variance = **2**

```latex
\sigma^2 = \frac{1}{n}\sum_{i=1}^{n}(x_i - \mu)^2 \qquad \sigma = \sqrt{\sigma^2}
```

The standard deviation is in the same units as the data: "values typically sit about 2 away from the mean."

**Population vs sample.** If your data is *every* member of the group, divide by n (as above). If it is only a *sample* from a bigger group, divide by **n - 1** to correct for a small bias in estimating the spread: 32 / 7 = 4.571, standard deviation 2.138. In NumPy, `np.var(data)` divides by n by default; use `ddof=1` for the sample version: `np.std(data, ddof=1)`. Pandas' `.std()` already uses n - 1 by default (which is why Lesson 003 results may differ slightly from NumPy's). Be consistent and know which one you use.

### 3.6 Distributions and the normal curve

A **probability distribution** says how likely each possible value is. Some examples:

| Distribution | Describes | Example |
| --- | --- | --- |
| **Uniform** | Every outcome equally likely | A fair die: each face 1/6 |
| **Bernoulli(p)** | One yes/no trial with success probability p | One attempt of an attack that works 30% of the time: p = 0.3 |
| **Binomial(n, p)** | Number of successes in n independent Bernoulli trials | How many of 20 attack attempts succeed |
| **Normal (Gaussian)** | A smooth bell curve around a mean | Heights, measurement noise, many averages |

**Expected value** is the long-run average: multiply each outcome by its probability and add. For a fair die: (1 + 2 + 3 + 4 + 5 + 6) / 6 = **3.5**. You can never roll a 3.5, but the average of many rolls approaches it. For a Binomial(n, p) the expected number of successes is n x p: 20 attempts at p = 0.3 gives 6 expected successes (though any single run could easily give 3 or 9).

**The normal distribution** is described by just two numbers: the **mean** (center) and the **standard deviation** (width). It appears everywhere because averages of many small random effects tend to look normal (see the central limit theorem below).

```latex
f(x) = \frac{1}{\sigma\sqrt{2\pi}}\exp\!\left(-\frac{(x-\mu)^2}{2\sigma^2}\right)
```

You do not need to memorize this formula. You do need this **rule of thumb (68-95-99.7)**:

| Range | Share of values inside |
| --- | --- |
| Mean plus or minus 1 standard deviation | about **68%** |
| Mean plus or minus 2 standard deviations | about **95%** |
| Mean plus or minus 3 standard deviations | about **99.7%** |

That is why a **z-score** above 3 is considered unusual: only about 0.3% of normal data lies that far out. Recall from Lesson 003:

```latex
z = \frac{x - \mu}{\sigma}
```

**Caution:** many real-world quantities (network traffic sizes, response times, login counts) are *not* normal. They are skewed or heavy-tailed, so "3 sigma" rules can give many false alarms or miss real attacks. Always look at a histogram first.

**A more robust alternative: median and MAD.** The **median absolute deviation (MAD)** is the median of |x - median|. A common robust score is `0.6745 * (x - median) / MAD`. Because medians ignore extreme values, planted outliers cannot hide themselves by inflating the spread (you will test this in the lab).

### 3.7 Sampling, the law of large numbers, and confidence

We almost never see all the data in the world. We see a **sample** and use it to estimate truth.

**Law of large numbers.** As the sample size grows, the sample average gets closer to the true average. Flip a fair coin 10 times and you might get 7 heads (70%). Flip it 100,000 times and you will be very close to 50%. Small samples are noisy.

**Standard error** measures how much a sample average typically wobbles from sample to sample:

```latex
\text{SE} = \frac{\sigma}{\sqrt{n}}
```

To cut the wobble in half you need **four times** as much data (because of the square root). This is why more evaluation data gives steadier conclusions, but with diminishing returns.

**Central limit theorem (intuition).** Averages of many independent samples tend to follow a normal curve, even if the underlying data is not normal. This is why the normal distribution is so useful for estimating how far a sample result may be from the truth.

**Confidence interval for a proportion.** Suppose you test a jailbreak prompt 50 times against a model and it works 40 times. The observed success rate is p = 40/50 = 0.8. How sure are we the *true* rate is 0.8? A common approximation:

```latex
p \pm 1.96\sqrt{\frac{p(1-p)}{n}}
```

Compute: p(1-p)/n = 0.8 x 0.2 / 50 = 0.0032. Square root = 0.0566. Times 1.96 = 0.111. So the 95% confidence interval is roughly **0.69 to 0.91**. The honest statement is "the success rate is likely between about 69% and 91%", not "80%".

How wide is the interval for other cases?

| Observed | n | Rough 95% interval (normal approx.) |
| --- | --- | --- |
| 8 of 10 | 10 | about 0.55 to 1.00 (very wide: 10 trials say little) |
| 80 of 100 | 100 | about 0.72 to 0.88 |
| 800 of 1,000 | 1,000 | about 0.77 to 0.83 |

For small samples or rates near 0 or 1, this simple formula is unreliable; the **Wilson interval** is better and is used in the lab. The principle matters more than the formula: **always report how many trials you ran.**

The same applies to accuracy on a test set: 90% accuracy measured on 100 examples is only 90 plus or minus about 6 points.

### 3.8 Softmax: turning scores into probabilities

Neural networks usually produce raw scores called **logits**, which can be any real numbers (positive, negative, huge). To interpret them as probabilities (all positive, summing to 1) we apply **softmax**:

```latex
\text{softmax}(z)_i = \frac{e^{z_i}}{\sum_j e^{z_j}}
```

In words: raise e (about 2.718) to the power of each score, then divide each result by the total. The exponential makes everything positive and exaggerates differences; dividing by the total makes them sum to 1.

**By hand.** Logits z = \[2.0, 1.0, 0.1\] for three classes (say benign, suspicious, malicious):

- e^2.0 = 7.389, e^1.0 = 2.718, e^0.1 = 1.105
- Sum = 11.212
- Probabilities: 7.389 / 11.212 = **0.659**, 2.718 / 11.212 = **0.242**, 1.105 / 11.212 = **0.099**

They add to 1.000. The biggest score gets the biggest probability.

**Temperature.** Divide the logits by a number T before softmax. This is exactly the "temperature" setting in LLM APIs.

| T | Logits after dividing | Probabilities | Effect |
| --- | --- | --- | --- |
| **0.5** (low) | \[4.0, 2.0, 0.2\] | **0.864, 0.117, 0.019** | Sharper: the top choice dominates (more predictable output) |
| **1.0** | \[2.0, 1.0, 0.1\] | **0.659, 0.242, 0.099** | The model's raw distribution |
| **2.0** (high) | \[1.0, 0.5, 0.05\] | **0.502, 0.304, 0.194** | Flatter: more randomness, more variety |

An LLM generates text by **sampling** the next token from this distribution. At low temperature it nearly always picks the most likely token; at high temperature it explores more. As T approaches 0 the choice becomes deterministic (always the top token).

**Warning:** softmax outputs *look* like confidence but are not guaranteed to be well calibrated. A network can output 0.99 for a wrong answer, especially on unusual inputs (including adversarial ones).

**Numerical stability.** `e` to the power of a large number overflows (e^1000 is infinity). The standard fix: subtract the maximum logit before exponentiating. This does not change the result, because the same factor cancels in the numerator and denominator. You will see it in the lab.

### 3.9 Cross-entropy: the loss for classification and for LLMs

In Lesson 002 we measured regression error with mean squared error. For classification we want to reward the model for putting **high probability on the correct class**. The standard loss is **cross-entropy**, which for one example is simply:

```latex
\text{loss} = -\ln\big(p_{\text{correct class}}\big)
```

The natural logarithm of a probability is negative, so we negate it to get a positive loss.

| Probability given to the correct class | Loss = -ln(p) | Meaning |
| --- | --- | --- |
| 0.99 | 0.010 | Very confident and right: tiny loss |
| 0.90 | 0.105 | Good |
| 0.50 | 0.693 | Unsure |
| 0.10 | 2.303 | Mostly wrong |
| 0.01 | 4.605 | Confidently wrong: large loss |

Notice how confidently wrong answers are punished severely. Training adjusts parameters (using gradient descent, exactly as in Lesson 002) to push this loss down on the training data.

**LLMs use the same loss.** An LLM reads text so far and outputs a probability distribution over every possible next token. The loss is -ln of the probability it gave to the **actual next token**. Training a language model is therefore "gradient descent on cross-entropy, repeated over trillions of tokens". The quantity people call **perplexity** is a transformation of this loss. We will meet it in the LLM lessons.

### 3.10 Correlation (and what it is not)

**Correlation** measures how two quantities move together, on a scale from -1 (perfectly opposite) through 0 (no linear relationship) to +1 (perfectly together). In NumPy: `np.corrcoef(a, b)`. Two cautions: correlation only detects **linear** patterns, and **correlation is not causation**. Ice cream sales and sunburn are correlated because both rise with hot weather. In security data, two alerts that spike together may share a hidden cause.

## 5. Step-by-Step Example: How the Spam Filter Really Works (Naive Bayes)

In Lesson 001 you used `MultinomialNB` as a black box. Now you can open it. The idea: use Bayes' rule with **several words** as evidence.

```latex
P(\text{spam} \mid \text{words}) \propto P(\text{spam}) \prod_{w} P(w \mid \text{spam})
```

The symbol with the proportional sign means "is proportional to" (we will normalize at the end), and the product symbol means multiply over every word. The "naive" assumption: given the class, words are treated as **independent** of one another. That is not true in real language ("free" and "prize" often appear together), but it works surprisingly well and makes the math simple.

**Setup (numbers we measured from our training emails).**

|  | Spam | Ham |
| --- | --- | --- |
| Prior P(class) | 0.4 | 0.6 |
| P("free" appears given class) | 0.6 | 0.1 |
| P("winner" appears given class) | 0.5 | 0.02 |

**New email contains both "free" and "winner".**

- Score for spam: 0.4 x 0.6 x 0.5 = **0.12**
- Score for ham: 0.6 x 0.1 x 0.02 = **0.0012**
- Normalize: total = 0.12 + 0.0012 = 0.1212. P(spam given words) = 0.12 / 0.1212 = **0.990**; P(ham given words) = **0.010**.

Two pieces of evidence that are each fairly common in ham but much more common in spam combine into a 99% belief. That is Bayes' rule applied repeatedly.

**Practical detail 1: logarithms.** Multiplying many small probabilities (hundreds of words) underflows to 0, so real implementations **add logarithms** instead: ln(a x b x c) = ln a + ln b + ln c. Then they turn the two log-scores back into probabilities with **softmax**. Softmax shows up again.

**Practical detail 2: smoothing.** If a word never appeared in spam during training, its probability would be 0 and would veto everything. **Laplace smoothing** adds 1 to every count so nothing is exactly zero.

**Why this matters for security:** you now see that the filter is nothing but word counts per class. An attacker can (1) add many innocent "ham" words to dilute spam evidence (called word salad or good-word attacks), (2) misspell trigger words so they fall outside the vocabulary (Lesson 001's `cl@im`), or (3) poison training emails so "free" looks harmless. You can now predict exactly why each works.

### 6.1 Simulating probability

```python
# lesson005_sim.py
import numpy as np

rng = np.random.default_rng(1)                       # seeded generator

rolls = rng.integers(1, 7, size=1_000_000)           # one million die rolls (1 to 6)
print('P(roll = 6)  ~', (rolls == 6).mean())         # about 0.1667  (1/6)

two = rng.integers(1, 7, size=(1_000_000, 2)).sum(axis=1)   # sum of two dice, one million times
print('P(sum = 7)   ~', (two == 7).mean())           # about 0.1667  (6/36)

print('law of large numbers (average of rolls):')
for n in [10, 100, 10_000, 1_000_000]:
    print(f'   n={n:>9,}  mean={rolls[:n].mean():.4f}')   # drifts toward 3.5 as n grows

# three heads in a row, simulated
flips = rng.integers(0, 2, size=(1_000_000, 3))      # 1 = heads
print('P(3 heads)   ~', (flips.sum(axis=1) == 3).mean())  # about 0.125
```

`(rolls == 6)` makes an array of True/False; `.mean()` of booleans is the fraction that are True. **Simulation** is a superpower: when the math is hard, you can estimate any probability by repeating the experiment many times.

### 6.2 Descriptive statistics and robustness

```python
# lesson005_stats.py
import numpy as np

data = np.array([2, 4, 4, 4, 5, 5, 7, 9])
print('mean            ', data.mean())              # 5.0
print('median          ', np.median(data))          # 4.5
print('variance (pop)  ', data.var())               # 4.0   (divide by n)
print('std (pop)       ', data.std())               # 2.0
print('variance (samp) ', data.var(ddof=1))         # about 4.571  (divide by n-1)
print('std (samp)      ', data.std(ddof=1))         # about 2.138

# --- The 68-95-99.7 rule by simulation ---
rng = np.random.default_rng(0)
z = rng.normal(0, 1, size=1_000_000)
for k in (1, 2, 3):
    print(f'within {k} std: {(np.abs(z) < k).mean():.4f}')   # about 0.683, 0.954, 0.997

# --- Masking: an outlier hides itself from the z-score ---
x = np.array([10.0, 11.0, 12.0, 13.0, 1000.0])
print('mean', x.mean(), ' median', np.median(x))            # 209.2 vs 12.0
z_scores = (x - x.mean()) / x.std(ddof=1)
mad = np.median(np.abs(x - np.median(x)))                    # median absolute deviation
robust = 0.6745 * (x - np.median(x)) / mad                   # robust (modified) z-score
print('z-scores     ', z_scores.round(2))                   # the 1000 only gets about 1.79: NOT flagged at 3
print('robust scores', robust.round(2))                     # the 1000 gets about 666: clearly flagged
```

**Expected:** the ordinary z-score of the value 1000 is only about 1.8, below the usual threshold of 3, so a z-score detector **misses** it, because the outlier inflated the standard deviation. The robust score flags it immediately. This is the masking effect you met in Lesson 003, now explained and fixed.

### 6.3 The base rate fallacy, computed and simulated

```python
# lesson005_bayes.py
import numpy as np

def posterior(prevalence, tpr, fpr):
    # Bayes' rule: P(attack | alert)
    return tpr * prevalence / (tpr * prevalence + fpr * (1 - prevalence))

tpr, fpr = 0.99, 0.01                                  # detects 99% of attacks; 1% false alarms
print('prevalence    P(attack | alert)')
for prev in [0.5, 0.1, 0.01, 0.001, 0.0001]:
    print(f'{prev:>10}    {posterior(prev, tpr, fpr):.4f}')
# about 0.99, 0.917, 0.50, 0.090, 0.0098

# --- Check by brute-force simulation ---
rng = np.random.default_rng(7)
n, prev = 2_000_000, 0.001
is_attack = rng.random(n) < prev                       # True for about 0.1% of events
alert = np.where(is_attack, rng.random(n) < tpr, rng.random(n) < fpr)   # detector behaviour
precision = (alert & is_attack).sum() / alert.sum()
print('simulated precision at prevalence 0.001:', round(precision, 4))   # about 0.09
print('alerts:', alert.sum(), ' real attacks among them:', (alert & is_attack).sum())
```

**What to notice:** the *same* detector (99% / 1%) is excellent when half of the events are attacks (posterior 0.99) and nearly useless when attacks are one in ten thousand (about 1%). The detector did not change; the **world** did.

### 6.4 Softmax, temperature, and cross-entropy

```python
# lesson005_softmax.py
import numpy as np

def softmax(logits, T=1.0):
    z = np.asarray(logits, dtype=float) / T      # temperature scaling
    z = z - z.max()                              # stability trick: subtract the max
    e = np.exp(z)
    return e / e.sum()

logits = [2.0, 1.0, 0.1]
for T in (0.5, 1.0, 2.0):
    print(f'T={T}:', softmax(logits, T).round(3))   # matches the table in Section 3.8

# Why subtract the max?
big = np.array([1000.0, 1001.0])
with np.errstate(over='ignore', invalid='ignore'):
    naive = np.exp(big) / np.exp(big).sum()     # exp(1000) overflows to inf, inf/inf = nan
print('naive softmax: ', naive)                 # [nan nan]
print('stable softmax:', softmax(big))           # [0.269 0.731]

# Cross-entropy for one example
for p in [0.99, 0.9, 0.5, 0.1, 0.01]:
    print(f'p(correct)={p:<5}  loss={-np.log(p):.3f}')

# Sampling the next token from a distribution (like an LLM does)
rng = np.random.default_rng(3)
vocab = ['the', 'a', 'cat']
for T in (0.5, 2.0):
    probs = softmax(logits, T)
    picks = rng.choice(vocab, size=1000, p=probs)
    counts = {w: int((picks == w).sum()) for w in vocab}
    print(f'T={T}: {counts}')                   # low T: mostly 'the'; high T: more variety
```

### 6.5 Mini project: opening up the spam filter

We will recompute scikit-learn's Naive Bayes predictions **by hand** (with log-probabilities, smoothing, and softmax), and check that they match.

```python
# lesson005_nb.py
import numpy as np
from sklearn.feature_extraction.text import CountVectorizer
from sklearn.naive_bayes import MultinomialNB

messages = [
    'win a free prize now', 'claim your free reward', 'you are a winner claim cash',
    'urgent claim prize money', 'meeting at noon tomorrow', 'lunch is free today join us',
    'please review the report', 'project deadline is friday',
]
labels = np.array(['spam', 'spam', 'spam', 'spam', 'ham', 'ham', 'ham', 'ham'])

vec = CountVectorizer()
X = vec.fit_transform(messages)                 # word counts, one row per message
counts = X.toarray()
model = MultinomialNB().fit(X, labels)          # scikit-learn's version (smoothing alpha = 1)

def my_class_logscore(cls, msg_counts):
    rows = counts[labels == cls]                 # training messages of this class
    word_totals = rows.sum(axis=0)               # how often each word appears in this class
    V = counts.shape[1]                          # vocabulary size
    logp = np.log((word_totals + 1) / (word_totals.sum() + V))    # Laplace-smoothed log P(word | class)
    prior = np.log((labels == cls).mean())                        # log P(class)
    return prior + msg_counts @ logp             # prior + sum of word log-probabilities

def my_predict(msg):
    m = vec.transform([msg]).toarray()[0]        # word counts of the new message
    scores = np.array([my_class_logscore(c, m) for c in model.classes_])
    e = np.exp(scores - scores.max())            # softmax over the two log-scores
    return e / e.sum()

for msg in ['claim your free prize', 'lunch is free today', 'project report deadline', 'cl@im your pr1ze']:
    mine = my_predict(msg)
    theirs = model.predict_proba(vec.transform([msg]))[0]
    print(f'{msg!r:28} classes={list(model.classes_)} mine={mine.round(3)} sklearn={theirs.round(3)} match={np.allclose(mine, theirs)}')
```

**Expected:** `match=True` on every row. The black box was just counting, adding logs, and applying softmax. For `cl@im your pr1ze` most words are outside the vocabulary and are ignored, so the result falls back toward the priors plus whatever known words remain ("your"): the evasion from Lesson 001 explained numerically.

**Troubleshooting**

| Problem | Fix |
| --- | --- |
| `match=False` | Check that you used smoothing `+ 1` and `+ V` exactly, and the same class order as `model.classes_` |
| Your simulation numbers differ slightly | Random sampling: use the same seed; small differences are normal |
| `RuntimeWarning: overflow` in exp | Subtract the maximum before exponentiating |
| Variance differs between NumPy and Pandas | NumPy defaults to n, Pandas to n - 1: set `ddof` explicitly |

### 6.6 Security lab A: reporting attack success honestly

**Learning objectives:** Understand why a handful of trials proves little, compute confidence intervals, and see how repeated attempts raise an attacker's odds.

**Safety:** pure statistics on simulated numbers; no real system is involved.

```python
# lesson005_asr.py   (attack success rate statistics, simulated)
import numpy as np

def wilson(k, n, z=1.96):
    # Wilson 95% interval for a proportion: better than the simple formula for small n
    p = k / n
    denom = 1 + z ** 2 / n
    center = (p + z ** 2 / (2 * n)) / denom
    half = z * np.sqrt(p * (1 - p) / n + z ** 2 / (4 * n ** 2)) / denom
    return round(center - half, 3), round(center + half, 3)

for k, n in [(8, 10), (40, 50), (800, 1000)]:
    print(f'{k}/{n} = {k/n:.2f}   95% interval {wilson(k, n)}')
# roughly (0.49, 0.94), (0.67, 0.89), (0.77, 0.82)

# --- How much does the observed rate wobble if the TRUE rate is 0.30? ---
rng = np.random.default_rng(5)
true_p = 0.30
for n in (10, 50, 500):
    rates = np.array([(rng.random(n) < true_p).mean() for _ in range(2000)])   # 2000 repeat experiments
    lo, hi = np.percentile(rates, [5, 95])
    print(f'n={n:>3}  mean={rates.mean():.3f}  std={rates.std():.3f}  90% of runs between {lo:.2f} and {hi:.2f}')
# std is about 0.145, 0.065, 0.021: it shrinks like 1/sqrt(n)

# --- An attacker only needs ONE success ---
for attempts in (1, 5, 10, 20, 45):
    p_any = 1 - (1 - true_p) ** attempts          # probability of at least one success
    print(f'{attempts:>3} attempts at p={true_p}: P(at least one success) = {p_any:.3f}')
```

**What to notice:**

1. With only 10 trials the interval is huge (roughly 0.49 to 0.94 for 8 of 10). A claim like "our defense stops 80% of attacks" based on 10 tests is nearly meaningless.
2. Run-to-run noise shrinks with the square root of n.
3. **A 30% per-attempt success rate is a 97% chance of success within 10 attempts.** For security, a defense that "usually works" against an attacker who can retry freely does not really work. LLMs sample their output randomly, so retrying the same attack prompt can give a different result each time. Always run each test many times and report the success rate with its interval.

### 6.7 Security lab B: why overconfidence leaks membership

**Learning objectives:** See the statistical signal behind **membership inference**: models tend to be more confident on examples they were trained on than on fresh ones, so confidence can reveal whether a record was in the training set.

**Safety:** synthetic data and a model you train yourself.

```python
# lesson005_membership.py   (toy membership-inference demonstration)
import numpy as np
from sklearn.datasets import make_classification
from sklearn.ensemble import RandomForestClassifier

X, y = make_classification(n_samples=400, n_features=20, n_informative=5,
                           flip_y=0.1, random_state=0)      # synthetic noisy dataset
X_in, y_in = X[:200], y[:200]            # 'members': used for training
X_out, y_out = X[200:], y[200:]          # 'non-members': never seen by the model

model = RandomForestClassifier(n_estimators=100, random_state=0).fit(X_in, y_in)

conf_in = model.predict_proba(X_in).max(axis=1)     # model's top probability on members
conf_out = model.predict_proba(X_out).max(axis=1)   # ... on non-members
print('mean confidence on members:     ', conf_in.mean().round(3))
print('mean confidence on non-members: ', conf_out.mean().round(3))

# The attacker's rule: guess 'member' when confidence is above a threshold
threshold = np.median(np.concatenate([conf_in, conf_out]))
correct = (conf_in > threshold).sum() + (conf_out <= threshold).sum()
print('attack accuracy:', correct / 400, '(0.5 would be random guessing)')
print('model accuracy on members:', model.score(X_in, y_in), ' on non-members:', model.score(X_out, y_out))
```

**Expected:** confidence on members is clearly higher than on non-members, and the attack accuracy is noticeably above 0.5, even though the attacker saw only output probabilities. The model also scores far better on members than non-members: that gap (overfitting, Lesson 002) is exactly what leaks.

**Security lessons:**

1. **Overfitting is a privacy risk**, not just an accuracy problem.
2. Returning full probability scores gives attackers more signal than returning only a label.
3. Mitigations include regularization, limiting or rounding confidence outputs, more training data, and **differential privacy** (adding carefully calibrated random noise during training). We study these later with the real membership inference attacks (Shokri et al., 2017).
4. This is a *statistical* attack: it does not break in anywhere, it just compares two distributions.

## 8. Cybersecurity Perspective

| Topic | Statistical idea | Why it matters |
| --- | --- | --- |
| **Detector evaluation** | Base rate fallacy, precision, false positive rate | A "99% accurate" classifier may produce mostly false alarms when attacks are rare; use realistic prevalence |
| **Alert fatigue** | Conditional probability | Too many false positives teach humans to ignore real alerts |
| **Retry attacks** | P(at least one success) = 1 - (1 - p)^k | Probabilistic defenses fail against persistent attackers; LLM outputs vary between runs |
| **Red-team reporting** | Confidence intervals | Report number of trials, success rate, and interval. Include the model version, temperature, and seed |
| **Data poisoning detection** | Distribution comparison, robust statistics | Compare incoming data to trusted data; use medians and MAD so planted outliers cannot hide |
| **Concept drift** | Changing distributions | Models degrade when real-world data shifts; attackers also exploit drift |
| **Membership inference** | Confidence distributions differ for members and non-members | Overfitting leaks training data (Lab B) |
| **Calibration and overconfidence** | Softmax probabilities need not be reliable | A model can be 99% sure and wrong, especially on adversarial or unfamiliar inputs |
| **Weak randomness** | Predictable pseudo-random numbers | Python's `random` and NumPy's generators are fine for experiments but **not for secrets or tokens**; use the `secrets` module (or `os.urandom`) for security-sensitive values |
| **Reproducibility** | Seeds | Record seeds and library versions so an attack result can be reproduced and verified; but never reuse a fixed seed in a security feature |
| **Differential privacy (preview)** | Adding calibrated noise | A formal defense against privacy leakage, studied in the defense lessons |

**Statistical habit for the rest of the course:** every time you measure something (an attack success rate, a detector's precision, a model's accuracy), write down **how many samples** you used, **what the base rate was**, and **how uncertain** the number is.

## 9. Common Mistakes and Misconceptions

| Mistake | Reality / fix |
| --- | --- |
| Confusing P(A given B) with P(B given A) | They are different; use Bayes' rule to convert (prosecutor's fallacy) |
| Ignoring the base rate | A highly accurate detector can still be mostly wrong on rare events |
| "99.9% accuracy means a great model" | A model that always says "benign" achieves this when attacks are 0.1% of cases |
| Gambler's fallacy | Independent events have no memory |
| Judging from tiny samples | 8 of 10 successes is very uncertain; report intervals |
| Using the mean on data with outliers | Use the median and MAD for robustness |
| Applying the 3-sigma rule to non-normal data | Check the histogram first; heavy tails produce many false alarms |
| Mixing population and sample variance | Know whether you divide by n or n - 1 (`ddof`) |
| Treating softmax output as true confidence | Softmax probabilities can be badly calibrated and overconfident |
| Correlation implies causation | Hidden common causes create correlations |
| Forgetting to subtract the max in softmax | Overflow produces NaN |
| Using `random` or a fixed seed for secrets | Use `secrets` for anything security-related |
| Believing a model is "deterministic" | LLMs sample randomly unless temperature is 0 (and even then outputs can vary across systems) |

## 10. Key Takeaways

- **Probability** quantifies uncertainty; **statistics** infers from data. ML combines them.
- Conditional probability P(A given B) is not P(B given A). **Bayes' rule** converts between them: posterior is proportional to likelihood times prior.
- The **base rate fallacy**: when attacks are rare, even an accurate detector produces mostly false alarms. Always compute precision at realistic prevalence.
- **Naive Bayes** spam filtering is counting words per class, adding logs, and applying softmax. You can now reproduce and attack it deliberately.
- Mean and standard deviation describe data but are fragile to outliers; the median and MAD are robust.
- The **normal curve** and the 68-95-99.7 rule underlie z-scores and many anomaly detectors, but real data may not be normal.
- Samples are noisy: the standard error shrinks as 1 over the square root of n. Report **confidence intervals** and the number of trials.
- **Softmax** turns logits into probabilities; **temperature** controls randomness; **cross-entropy** punishes confident wrong answers and is the loss behind classifiers and LLMs.
- Security: attackers retry (1 - (1 - p)^k), probabilities leak information (membership inference), and randomness quality matters.
