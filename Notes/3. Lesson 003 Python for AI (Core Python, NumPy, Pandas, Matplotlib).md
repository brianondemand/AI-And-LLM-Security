### 2.3 The big idea: think in whole arrays, not loops

In Lesson 002 you wrote `for x in xs:` to process one number at a time. In scientific Python, the habit changes: **apply an operation to the whole array at once.** This is called **vectorization**. It makes code shorter, clearer, and often 10 to 100 times faster, because the loop runs in optimized compiled code instead of slow Python. Deep learning frameworks (PyTorch, TensorFlow) work exactly the same way, so learning this habit now pays off for the rest of the course.

name = 'alice'          # str  (text)

### 3.2 NumPy: fast math on arrays

**What is an array?** A grid of numbers, all of the same type. A 1-D array is a list of numbers (a **vector**). A 2-D array is a table of numbers (a **matrix**). A 3-D array is a stack of tables, and so on. In AI, almost everything is an array: a photo is a 3-D array of pixel values, a batch of sentences is a 2-D array of token numbers, and a neural network's parameters are arrays of weights.

**Key vocabulary:**

| Term | Meaning |
| --- | --- |
| **Array** (`ndarray`) | NumPy's main data structure |
| **Shape** | The size along each dimension, e.g. `(2, 3)` means 2 rows, 3 columns |
| **dtype** | The data type of the elements (`int64`, `float64`, ...) |
| **Axis** | A dimension. `axis=0` runs down the rows; `axis=1` runs across the columns |
| **Vectorization** | Applying an operation to all elements at once without a Python loop |
| **Broadcasting** | NumPy's rule for combining arrays of different shapes |

Save as `lesson003_numpy.py`:

```python
# lesson003_numpy.py
import numpy as np                   # 'np' is the universal nickname

# --- Creating arrays ---
a = np.array([1, 2, 3])              # 1-D array (vector)
print(a, a.shape, a.dtype)           # [1 2 3] (3,) int64   (dtype may differ by platform)

M = np.array([[1, 2, 3],
              [4, 5, 6]])            # 2-D array (matrix)
print(M.shape)                       # (2, 3): 2 rows, 3 columns

print(np.zeros((2, 2)))              # 2x2 of zeros
print(np.arange(0, 10, 2))           # [0 2 4 6 8]
print(np.linspace(0, 1, 5))          # 5 evenly spaced numbers from 0 to 1

# --- Vectorized math: no loops needed ---
print(a * 2)                         # [2 4 6]        every element times 2
print(a + a)                         # [2 4 6]        element-wise add
print(a ** 2)                        # [1 4 9]        every element squared
print([1, 2, 3] * 2)                 # [1, 2, 3, 1, 2, 3]  <- a Python LIST repeats! Not the same.

# --- Statistics and reductions ---
print(M.sum(), M.mean())             # 21 3.5
print(M.sum(axis=0))                 # [5 7 9]   sum down each column
print(M.sum(axis=1))                 # [ 6 15]   sum across each row

# --- Indexing and slicing ---
print(M[0, 1])                       # 2         row 0, column 1
print(M[:, 0])                       # [1 4]     all rows, column 0
print(M[1, :])                       # [4 5 6]   row 1, all columns
print(M[M > 3])                      # [4 5 6]   boolean mask: keep elements greater than 3

# --- Broadcasting: combine different shapes ---
print(M + np.array([10, 20, 30]))    # adds [10 20 30] to EVERY row
#   [[11 22 33]
#    [14 25 36]]

# --- Dot product ---
u = np.array([1, 2, 3])
v = np.array([4, 5, 6])
print(np.dot(u, v))                  # 32  ->  1*4 + 2*5 + 3*6

# --- Reproducible randomness ---
rng = np.random.default_rng(42)      # the number 42 is a 'seed': same seed, same random numbers
print(rng.normal(0, 1, size=3))      # 3 samples from a bell curve (mean 0, std 1)
```

**Step-by-step: why a dot product matters.** The dot product multiplies matching elements and adds them up:

```latex
u \cdot v = \sum_{i=1}^{n} u_i v_i
```

For u = \[1, 2, 3\] and v = \[4, 5, 6\]: 1 x 4 = 4, 2 x 5 = 10, 3 x 6 = 18, and 4 + 10 + 18 = **32**. This single operation is the heart of a neuron: a neuron multiplies each input by a weight and adds them up, which is exactly a dot product of the **inputs** and the **weights**. We will use this heavily in Lesson 004 (linear algebra) and when we build neural networks.

**Speed comparison.** Run this to see vectorization's payoff on your own machine:

```python
# lesson003_speed.py
import time
import numpy as np

N = 1_000_000
py_list = list(range(N))
np_arr = np.arange(N)

t0 = time.perf_counter()
total_py = sum(x * x for x in py_list)         # pure Python loop
t1 = time.perf_counter()
total_np = int((np_arr * np_arr).sum())        # vectorized
t2 = time.perf_counter()

print('same answer:', total_py == total_np)
print(f'python: {t1 - t0:.4f}s   numpy: {t2 - t1:.4f}s')
```

Exact numbers depend on your hardware, but NumPy should be clearly faster. Record your speedup in your notes.

### 3.3 Rebuilding gradient descent with NumPy

Here is Lesson 002's training loop, rewritten with arrays. Compare it with the list version: the logic is identical, but there are no inner loops.

```python
# lesson003_gd_numpy.py
import numpy as np

x = np.array([1.0, 2.0, 3.0])        # inputs as an array
y = np.array([2.0, 4.0, 6.0])        # labels as an array

w = 0.0
lr = 0.05
losses = []                          # we will keep the loss history to plot later

for step in range(1, 21):
    preds = w * x                    # predictions for ALL examples at once
    errors = preds - y               # element-wise subtraction
    loss = np.mean(errors ** 2)      # mean squared error
    grad = 2 * np.mean(errors * x)   # same formula as Lesson 002
    w = w - lr * grad                # update rule
    losses.append(loss)
    print(f'step {step:2d}  loss={loss:8.4f}  w={w:.4f}')
```

You should see exactly the same numbers as Lesson 002 (step 1 loss 18.6667, w 0.9333; step 2 w 1.4311). The `np.mean(errors * x)` replaces `sum(...) / len(...)`.

**Level up: two parameters (slope and intercept).** Real models almost always have a **bias** (an intercept) as well as a weight. Now the model is **y-hat = w \* x + b**, and we need a gradient for *each* parameter. Our new data follows y = 2x + 1.

```python
# lesson003_gd_two_params.py
import numpy as np

x = np.array([1.0, 2.0, 3.0])
y = np.array([3.0, 5.0, 7.0])        # true relationship: y = 2x + 1

w, b = 0.0, 0.0                      # two parameters, both start at zero
lr = 0.05

for step in range(1, 2001):
    preds = w * x + b                # model: weight times input plus bias
    errors = preds - y
    loss = np.mean(errors ** 2)
    grad_w = 2 * np.mean(errors * x) # slope of the loss with respect to w
    grad_b = 2 * np.mean(errors)     # slope of the loss with respect to b
    w -= lr * grad_w                 # '-=' is shorthand for w = w - ...
    b -= lr * grad_b
    if step % 400 == 0 or step == 1:
        print(f'step {step:4d}  loss={loss:.6f}  w={w:.4f}  b={b:.4f}')
```

**Expected:** the loss shrinks steadily and w and b approach **2** and **1**. It needs more steps than the one-parameter version because the two parameters interact, which is normal. This is the exact structure of a real network's training loop: *one gradient per parameter, all updated together.* The only thing that changes at scale is the number of parameters and the way gradients are computed (backpropagation, Stage 2).

### 3.4 Pandas: tables of data

**What is Pandas?** A library for working with **tabular data**: rows are examples, columns are features. If NumPy is a grid of raw numbers, Pandas is a grid with **column names, row labels, mixed types, and missing-value handling**. Almost every real dataset you will meet (CSV files, logs, exports from databases) is loaded into Pandas first.

**Two core objects:**

| Object | What it is | Example |
| --- | --- | --- |
| **Series** | One labeled column | The `age` column |
| **DataFrame** | A whole table of Series sharing an index | A table of users |

Save as `lesson003_pandas.py`:

```python
# lesson003_pandas.py
import pandas as pd
import numpy as np

# --- Build a small DataFrame from a dictionary ---
df = pd.DataFrame({
    'user':   ['alice', 'bob', 'carol', 'dave', 'erin'],
    'age':    [34, 28, np.nan, 45, 31],        # np.nan = missing value
    'role':   ['admin', 'dev', 'dev', 'admin', 'dev'],
    'logins': [120, 85, 60, 15, 200],
})
print(df)

# --- Inspect (do this FIRST with any new dataset) ---
print(df.head(3))        # first 3 rows
print(df.shape)          # (5, 4): 5 rows, 4 columns
df.info()                # column names, types, and how many non-missing values
print(df.describe())     # count, mean, std, min, quartiles, max for numeric columns

# --- Selecting data ---
print(df['user'])                      # one column (a Series)
print(df[['user', 'logins']])          # several columns (a DataFrame)
print(df.loc[0])                       # row by label (the first row)
print(df.iloc[1:3])                    # rows by position

# --- Filtering with conditions ---
print(df[df['logins'] > 100])                       # rows where logins > 100
print(df[(df['role'] == 'dev') & (df['logins'] > 70)])   # combine with & (and), | (or). Parentheses required!

# --- Missing values ---
print(df['age'].isna().sum())          # how many values are missing in 'age' -> 1
df['age'] = df['age'].fillna(df['age'].median())    # fill with the median

# --- New columns, sorting, grouping ---
df['logins_per_year_age'] = df['logins'] / df['age']
print(df.sort_values('logins', ascending=False))
print(df.groupby('role')['logins'].mean())          # average logins per role

# --- Saving and loading ---
df.to_csv('users.csv', index=False)    # write to disk
df2 = pd.read_csv('users.csv')         # read it back
print(df2.equals(df))                  # usually True (types are re-inferred)
```

**Key ideas**

- **Always inspect first.** `head()`, `shape`, `info()`, `describe()` should be your reflex. Many real bugs and many *attacks* (poisoned rows, strange values) are visible in these four commands.
- **Boolean filtering** is like a database `WHERE` clause. `df[condition]` keeps rows where the condition is True.
- **`groupby`** is like SQL `GROUP BY`: split into groups, compute something per group.
- **Missing values (`NaN`)** need a deliberate decision: drop them, fill them, or investigate why they are missing. We cover this properly in Module 1.7 (data preprocessing).

### 3.5 Matplotlib: seeing your data

**Why plot?** Numbers hide patterns that pictures show instantly: outliers, clusters, trends, and whether training is working. You will plot a loss curve in nearly every AI project.

```python
# lesson003_plots.py
import numpy as np
import matplotlib.pyplot as plt      # 'plt' is the universal nickname

# --- Data: reuse our gradient descent, saving the loss at each step ---
x = np.array([1.0, 2.0, 3.0]); y = np.array([2.0, 4.0, 6.0])
w, lr, losses = 0.0, 0.05, []
for _ in range(30):
    errors = w * x - y
    losses.append(np.mean(errors ** 2))
    w -= lr * 2 * np.mean(errors * x)

# --- Figure with two panels side by side ---
fig, axes = plt.subplots(1, 2, figsize=(10, 4))   # 1 row, 2 columns of plots

axes[0].plot(losses, marker='o')                  # line plot of loss over steps
axes[0].set_title('Training loss')
axes[0].set_xlabel('step')
axes[0].set_ylabel('MSE loss')

axes[1].scatter(x, y, label='data')               # scatter plot of the raw data
xs = np.linspace(0, 4, 50)
axes[1].plot(xs, w * xs, color='red', label=f'model: y = {w:.2f}x')   # the learned line
axes[1].set_title('Data and learned line')
axes[1].legend()

plt.tight_layout()                                # avoid overlapping labels
plt.savefig('lesson003_plots.png', dpi=120)       # save to a file (works on any machine)
plt.show()                                        # open a window (skip on headless servers)
```

Open `lesson003_plots.png`. The left chart should show the loss falling fast and flattening; the right should show a red line passing through the three points. If you run on a machine without a display, remove `plt.show()` and rely on `savefig`.

## 5. Step-by-Step Example: Shapes and Broadcasting

Shape errors are the number-one source of bugs in AI code, so let us slow down and do one carefully.

**Problem:** We have 3 students' scores on 2 exams, and we want to subtract each exam's average so scores are "centered".

```python
import numpy as np

scores = np.array([[80, 90],
                   [70, 60],
                   [90, 75]])           # shape (3, 2): 3 students (rows), 2 exams (columns)

exam_means = scores.mean(axis=0)        # average DOWN the rows -> one mean per exam
print(exam_means)                       # [80.  75.]    shape (2,)

centered = scores - exam_means          # (3, 2) minus (2,) -> broadcast
print(centered)
# [[  0.  15.]
#  [-10. -15.]
#  [ 10.   0.]]
```

**What happened, in steps:**

1. `scores` has shape (3, 2). `exam_means` has shape (2,).
2. NumPy lines up shapes from the **right**. The 2 matches the 2. The missing first dimension is treated as "repeat this row as many times as needed".
3. So `exam_means` is effectively stretched to \[\[80, 75\], \[80, 75\], \[80, 75\]\] **without copying memory**, then subtracted element by element.
4. Check: student 1's exam 1 score 80 minus mean 80 = 0. Exam 2: 90 minus 75 = 15. Correct.

The broadcasting rule: dimensions are compatible when they are **equal** or one of them is **1** (or missing). If they are not, NumPy raises a `ValueError` about shapes. Whenever you see that error, print `.shape` of everything involved.

## 6. Practical Demonstration: Mini Project (Login Log Analysis)

**Learning objectives:** Use Pandas, NumPy, and Matplotlib together on a security-flavored dataset; practice the inspect, summarize, flag, and plot workflow; see why simple statistics have weaknesses.

**Tools:** Python 3.10+, `numpy`, `pandas`, `matplotlib` (already installed). **Environment:** your `.venv`. **Safety:** all data is synthetic and generated locally.

```python
# lesson003_logins.py
import numpy as np
import pandas as pd
import matplotlib.pyplot as plt

# ---------- 1. Generate a synthetic login log ----------
rng = np.random.default_rng(42)                     # seed makes the data reproducible
n = 200
df = pd.DataFrame({
    'user': rng.choice(['alice', 'bob', 'carol', 'dave'], size=n),
    'hour': rng.integers(8, 19, size=n),            # working hours 8 to 18
    'failed_attempts': rng.poisson(1.0, size=n),    # usually 0 to 3 failures
    'mb_sent': rng.normal(50, 10, size=n).round(1), # about 50 MB, give or take
})

# inject 3 suspicious sessions (rows 10, 77, 150): odd hour, many failures, huge upload
bad = [10, 77, 150]
df.loc[bad, 'hour'] = [3, 2, 4]
df.loc[bad, 'failed_attempts'] = [25, 30, 22]
df.loc[bad, 'mb_sent'] = [400.0, 520.0, 380.0]

df.to_csv('logins.csv', index=False)

# ---------- 2. Load and inspect ----------
df = pd.read_csv('logins.csv')
print(df.head())
df.info()
print(df.describe())

# ---------- 3. Summarize per user ----------
print(df.groupby('user')[['failed_attempts', 'mb_sent']].mean().round(2))

# ---------- 4. Flag anomalies with a z-score ----------
mean, std = df['mb_sent'].mean(), df['mb_sent'].std()
df['z_mb'] = (df['mb_sent'] - mean) / std           # how many std devs from average
suspicious = df[(df['z_mb'].abs() > 3) | (df['failed_attempts'] > 10)]
print('\nFLAGGED ROWS:')
print(suspicious)
print('std of mb_sent WITH outliers:', round(std, 1))
clean_std = df.loc[~df.index.isin(bad), 'mb_sent'].std()
print('std of mb_sent WITHOUT them:  ', round(clean_std, 1))

# ---------- 5. Plot ----------
fig, axes = plt.subplots(1, 2, figsize=(10, 4))
axes[0].hist(df['mb_sent'], bins=30)
axes[0].set_title('Distribution of MB sent')
axes[1].scatter(df['failed_attempts'], df['mb_sent'], alpha=0.6)
axes[1].scatter(suspicious['failed_attempts'], suspicious['mb_sent'], color='red', label='flagged')
axes[1].set_xlabel('failed attempts'); axes[1].set_ylabel('MB sent'); axes[1].legend()
plt.tight_layout()
plt.savefig('lesson003_logins.png', dpi=120)
print('saved lesson003_logins.png')
```

```bash
python lesson003_logins.py
```

**Line-by-line highlights**

- `rng.choice([...], size=n)` picks random users; `rng.integers(8, 19, ...)` gives hours 8 to 18; `rng.poisson(1.0, ...)` produces small counts (a Poisson distribution is a good model of rare events like failed logins); `rng.normal(50, 10, ...)` gives bell-curve data.
- `df.loc[bad, 'hour'] = [3, 2, 4]` writes values into specific rows and one column. This is how we plant our "attacks".
- `df['z_mb'] = (df['mb_sent'] - mean) / std` is the z-score: the entire column is processed at once (vectorization).
- `df[(A) | (B)]` keeps rows meeting either condition. `~` means "not".

**Expected results:** the three injected rows (index 10, 77, 150) appear in the flagged table with large z-scores and 22 to 30 failed attempts. The standard deviation printed **with** the outliers is far larger than **without** them. That reveals an important weakness: *extreme outliers inflate the very statistics used to detect them* (this is called **masking**). If there had been more attacks, the z-score threshold could have missed some. Real systems use more robust methods, which we will meet in anomaly detection later.

**Troubleshooting**

| Problem | Fix |
| --- | --- |
| `ModuleNotFoundError: No module named 'pandas'` | Activate `.venv` and run `pip install pandas` |
| `plt.show()` hangs or errors on a server | Remove it and use `savefig` only |
| Your numbers differ slightly from mine | Check the seed (42) and library versions; random generators can vary across versions |
| `ValueError: ... shapes ...` | Print `.shape` for each array involved |
| Pandas `SettingWithCopyWarning` | Use `df.loc[rows, 'col'] = value` instead of chained indexing like `df[rows]['col'] = value` |

In the security track you will use exactly these skills to: batch-send test prompts to an LLM API and tabulate which succeeded, measure how accuracy drops under adversarial perturbation, and chart results for a pentest report.

## 8. Cybersecurity Perspective

Python itself is part of the AI attack surface. These are real, well-documented risk areas; you will meet them again in the security track.

| Risk | What happens | Defensive habit |
| --- | --- | --- |
| **Unsafe deserialization (pickle)** | Python's `pickle` format can execute arbitrary code when loaded. Many model and data files (including some `.pkl` and older PyTorch `.pt/.bin` checkpoints) rely on it. Loading an untrusted one can mean running an attacker's code | Never load model or data files from untrusted sources. Prefer safer formats such as `safetensors` for model weights, and check the library docs for safe-loading options |
| **NumPy `allow_pickle`** | `np.load(file, allow_pickle=True)` can execute code from a crafted `.npy`/`.npz`. Recent NumPy versions default to `allow_pickle=False` | Leave it at `False` unless you fully trust the file |
| **Malicious or typosquatted packages** | An attacker publishes a package with a name similar to a popular one (for example a one-letter difference) or compromises a dependency | Check package names carefully, install only what you need, pin versions, and review `requirements.txt` |
| **Dependency drift and vulnerabilities** | Unpinned dependencies change over time; old versions may have known CVEs | Pin versions (`pip freeze > requirements.txt`) and audit with tools such as `pip-audit` |
| **Using the wrong environment** | Installing globally mixes packages and can break system tools | One virtual environment per project; never `sudo pip install` into the system Python |
| **Secrets in notebooks and scripts** | API keys pasted into code or notebooks get committed to Git or shared | Load keys from environment variables or a secrets file excluded from Git; clear notebook outputs before sharing |
| **Untrusted data files** | CSVs and logs may contain unexpected values, huge files, or text that becomes a formula when opened in a spreadsheet (CSV/formula injection) | Validate columns and types, cap file sizes, and be careful exporting untrusted cells to spreadsheets |
| **Poisoned or malformed data** | Missing values, impossible numbers, or planted rows can bias a model | Inspect with `head`, `describe`, `isna`, and plots before training (exactly what you did in the mini project) |
| **Weak randomness and reproducibility** | Without seeds, you cannot reproduce an experiment or an attack result | Set and record seeds for every experiment; log library versions in test reports |

**Security habit to start now:** treat *model files, datasets, and Python packages* as **untrusted code and input** until verified, exactly as you would treat a downloaded binary or a web form field. This mindset is the foundation of AI supply-chain security.

**Pentester's note:** In AI red-team engagements, a common first move is to look at how a target loads models and data, because code execution through an unsafe loader is a far bigger finding than a model misclassifying an input. We will examine this on intentionally vulnerable local labs later.

## 9. Common Mistakes and Misconceptions

| Mistake | Why it happens | Fix |
| --- | --- | --- |
| Forgetting to activate the venv, then "module not found" | New terminal windows are not activated automatically | Run `source .venv/bin/activate`; check the `(.venv)` prefix |
| Thinking a list and a NumPy array behave the same | `[1, 2] * 2` repeats; `np.array([1, 2]) * 2` multiplies | Convert with `np.array(...)` before math |
| Integer vs float surprises | Arrays inherit the type of their contents, so `np.array([1, 2, 3])` is integers | Write `1.0` or use `dtype=float` when you need decimals |
| Shape mismatches | Mixing `(3,)`, `(3, 1)`, and `(1, 3)` | Print `.shape` everywhere; use `.reshape(...)` deliberately |
| Modifying a view and changing the original | Slicing an array often returns a *view* of the same memory, not a copy | Use `.copy()` when you need an independent array |
| `&` vs `and` in Pandas filters | `and` does not work element-wise | Use `&`, \` |
| Chained indexing (`df[cond]['col'] = x`) | Writes to a temporary copy | Use `df.loc[cond, 'col'] = x` |
| Never inspecting data | Jumping straight to modeling | `head`, `info`, `describe`, a quick plot, every time |
| Ignoring randomness | Results change from run to run | Use a seeded generator, e.g. `np.random.default_rng(42)` |
| Running code you do not understand from a tutorial | Copy-paste habit | Read it, run it in a throwaway venv, and explain each line (as we do here) |
| Using `pip install` as root or globally | Convenience | Use virtual environments |

## 10. Key Takeaways

- Python is the steering wheel; compiled libraries are the engine. AI work means calling fast libraries, not writing slow loops.
- **Core Python** you need: types, lists, dicts, loops, functions, comprehensions, imports.
- **NumPy** gives fast arrays. Think in whole arrays: **vectorize**. Learn **shape**, **axis**, and **broadcasting**; most bugs are shape bugs.
- The **dot product** (multiply and add) is the basic operation of a neuron.
- Gradient descent generalizes directly from one parameter to many: *one gradient per parameter, update them all together.*
- **Pandas** is for tabular data; always inspect first (`head`, `info`, `describe`), filter with boolean conditions, summarize with `groupby`.
- **Matplotlib** makes patterns visible: loss curves, scatter plots, histograms.
- Statistics like the mean and standard deviation can be distorted by the very outliers you are hunting.
- Python packages, data files, and model files are **supply-chain risks**: pickle can execute code, packages can be malicious, and secrets leak through notebooks.
